# Obelisk

**Универсальный VPN-клиент для OpenWrt.
Один клиент, два ядра, вся подписка целиком.**

В одной подписке спокойно соседствуют VLESS поверх REALITY, Trojan по gRPC,
Shadowsocks и Hysteria2. Ни одно ядро не тянет всё это одинаково хорошо. Obelisk
читает подписку, определяет, какое ядро реально способно нести каждый сервер, и
запускает оба: sing-box впереди владеет туннелем, Xray работает за ним для
протоколов, которые умеет только он. Снаружи — один список серверов и один
переключатель.

## Зачем это

VPN на роутере, а не на каждом устройстве — правильная форма для дома: телевизор,
консоль и телефон гостя получают одинаковую маршрутизацию, и никто ничего не
ставит. Под OpenWrt выбор тут скудный, а то, что есть, обычно выбирает одно ядро
и на этом останавливается.

Obelisk сделан именно под роутер:

- **Оба ядра, выбор на каждый сервер.** Не «поддерживает Xray *или* sing-box», а
  оба сразу, и решение принимается по тому, что реально требует протокол.
- **Ядра остаются стоковыми.** Это отдельные исполняемые файлы, скачанные из их
  собственных релизов, и они не патчатся. Обновление ядра — замена файла, а не
  пересборка Obelisk.
- **Один статический бинарник.** Чистый Go, `CGO_ENABLED=0`, веб-интерфейс вшит
  внутрь. Развёртывание — копирование одного файла. Никакой сборки фронтенда,
  никаких `node_modules`, никакого рантайма.
- **Не лезет к чужому.** Obelisk владеет ровно одной таблицей nftables и не
  трогает ничьи другие. Он определяет zapret и уживается с ним — об этом ниже,
  потому что это оказалось сложнее, чем звучит.

## Что умеет

**Подписки.** Share-ссылки, base64, Clash YAML, sing-box JSON и Xray JSON. Панели
отдают разные форматы разным клиентам, поэтому User-Agent выбирается для каждой
подписки, а полученный формат показывается — обычно это и есть всё объяснение
подписки, которая выглядит пустой.

**Сплит-туннелирование в трёх формах.** Один список и переключатель, который
говорит, как его читать: *в туннель только список*, *в туннель всё, кроме
списка*, или *всё в туннель*. В поле можно вставить что угодно — ссылку из
адресной строки, `*.wildcard`, IP, подсеть, ключевое слово — и Obelisk отчитается,
как понял каждую строку.

**Маршруты провайдера, объединённые с вашими.** Многие подписки присылают свой
список того, что должно идти мимо туннеля. Obelisk импортирует его и применяет
**под** вашими правилами: ничего из написанного вами не может быть перебито и
ничего не теряется при смене провайдера.

**Режимы перехвата.** TUN, TPROXY, REDIRECT или только прокси, переключаются на
ходу.

**Split-DNS, который действительно split.** Имена, до которых пойдут через
туннель, разрешаются через него; всё остальное — напрямую. То, что это строится
из тех же маршрутных правил, а не объявляется, и есть разница между обещанием и
поведением.

**Проверка доступности как два вопроса.** «Работает ли интернет» спрашивается у
ресурсов, которые не блокируют. «Несёт ли что-нибудь туннель» спрашивается у
заблокированных, **через прокси самого ядра** — достижимость такого хоста
единственное доказательство, что трафик действительно ушёл в туннель. Одна
лампочка «подключено» их не различает, и именно этот отказ она прячет.

**Живой трафик: по маршруту и по устройствам.** График пропускной способности
сложен по тому, куда ушли байты — в туннель или мимо. Панель соединений
группирует по машинам в локальной сети, имена берутся из DHCP-аренд роутера.

**Автоподключение, которое переживает перезагрузку.** Включено по умолчанию и
делает повторы: роутер поднимается после отключения света раньше, чем WAN успеет
дозвониться, и одна попытка провалилась бы на канале, до готовности которого
оставались секунды, — а туннель остался бы выключенным, пока кто-нибудь не
заметит. Отступает, как только вы нажали «подключить» или «отключить» руками:
клиент, который переподключается вопреки только что принятому решению, хуже
того, который не подключается сам вовсе.

**CLI не для галочки.** Всё, что делает браузер, делает и командная строка,
против того же демона.

## Установка

### Docker (рекомендуется)

```bash
git clone https://github.com/HilistonGit/Obelisk.git
cd obelisk
docker compose up -d
docker compose logs | grep token      # токен доступа к веб-интерфейсу
```

Дальше открыть `http://<роутер>:24080`.

Host-сеть для прозрачных режимов обязательна: Obelisk должен ставить свой
интерфейс и свои правила на сетевой стек самого роутера.

### Бинарник

```bash
make release                       # все архитектуры OpenWrt в dist/
scp dist/obelisk-linux-arm64 root@router:/usr/bin/obelisk
ssh root@router 'obelisk core install all && obelisk daemon'
```

Кросс-компиляция под `amd64`, `arm64`, `armv7`, `armv6`, `mipsle`, `mips` и
`riscv64`. Ядра скачиваются в рантайме под ту архитектуру и ту libc, которые у
роутера на самом деле есть: сборки под musl и glibc не взаимозаменяемы, и не та
падает с «файл не найден» на файл, который лежит на месте.

## Использование

```bash
obelisk parse   <подписка>         # что в ней
obelisk plan    <подписка>         # какое ядро возьмёт каждый сервер и почему
obelisk route add "https://www.youtube.com/watch?v=..." "*.googlevideo.com" 142.250.0.0/15
obelisk route test rutracker.net   # что будет с этим адресом
obelisk core update all            # обновить ядра на месте, с откатом
obelisk daemon                     # веб-интерфейс, API, ядра
```

## Соседство с обходом DPI

Если у вас работает [zapret](https://github.com/bol-van/zapret) или подобное, эти два
инструмента мешают друг другу так, что ни один об этом не сообщает. В режиме
TUN каждое соединение из локальной сети терминируется ядром и открывается заново
уже от роутера; пакеты, которые вбрасывает zapret, порождаются локально, а
туннель с `auto_route` ловит именно такие. Фейки уходят в туннель вместо
провайдера, DPI их не видит, и передачи к хостам из списка zapret встают на
середине.

Измерено на живом роутере, одно и то же скачивание 10 МБ:

| | результат |
|---|---|
| туннель выкл, zapret вкл | 10 000 000 Б @ 8.7 МБ/с |
| туннель вкл, zapret вкл, без мер | **21 102 Б @ 844 Б/с** |
| туннель вкл, zapret **выкл** | 10 000 000 Б @ 9.2 МБ/с |
| туннель вкл, zapret вкл, режим `share` | 10 000 000 Б @ 7.6 МБ/с |

Obelisk определяет zapret и добавляет одно правило маршрутизации, которое
выпускает его пакеты мимо туннеля. Конфигурация zapret не трогается ни в одном
байте — его стратегии приходят из апстрима и часто меняются. После этого оба
работают: zapret держит прямой путь, туннель берёт то, что zapret не вытягивает.

## Как устроено

```
        LAN ──► tun / tproxy / redirect
                     │
                sing-box  ── инбаунды, маршрутизация, DNS
                     │
        ┌────────────┴────────────┐
     напрямую                  прокси
                                 │
                    ┌────────────┴────────────┐
            свой аутбаунд              SOCKS-мост ──► Xray
      (VLESS, Trojan, SS, Hysteria2)             (XHTTP и всё, что
                                                  умеет только Xray)
```

Подробный разбор — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md): топология,
движок маршрутизации, метки в firewall и список того, что оказалось сломано на
реальном железе, вместе с тем, как это нашлось.

## Сборка

```bash
make check      # gofmt, go vet, go test и smoke-тест веб-интерфейса
make build      # один бинарник под текущую машину
make release    # все архитектуры
```

Интерфейс — нативные ES-модули и CSS без сборки, вшитые через `go:embed`.
`web/smoke.mjs` прогоняет его под Node с заглушкой DOM и обходит все экраны;
именно это ловит обработчик, потерянный при рефакторинге, — в браузере такой
отказ выглядит как пустая страница и одна строка в консоли.

## Статус

Работает и используется ежедневно на Raspberry Pi 4 с OpenWrt 24.10. Шероховатости
возможны; issues и pull request'ы приветствуются.
